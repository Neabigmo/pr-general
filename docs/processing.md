# 数据处理流程

1. **读取四个来源**：读取 NPInter 主表、NPInter binding-site、NPInter miRNA 和 RCSB PDB 候选表。
2. **来源条件检查**：只保留来源字段正确、证据或 PDB 标识满足要求的记录；binding-site 窗口不超过 `config/pipeline.yaml` 中的上限（当前为 200 nt）。
3. **序列解析**：补齐并规范化蛋白和 RNA 序列；缺少任一端序列的记录不能进入后续筛选。
4. **D1 质量和长度检查**：蛋白只接受标准 20 种氨基酸且长度为配置范围（当前为 40–2,000 aa）；RNA 只接受 A、C、G、U 且长度为配置范围（当前为 10–500 nt）。
5. **D2 exact 去重**：完全相同的 protein–RNA 序列组合只保留一条代表记录。
6. **D3 RNA90 去冗余**：在同一个蛋白内部，对相似 RNA 聚类，每个 RNA90 簇保留代表样本。
7. **单蛋白限额**：限制同一个蛋白进入预测队列的数量，避免少数高频蛋白占满队列。
8. **Protein30 家族限额**：同一个蛋白家族最多占目标队列的 5%。
9. **最终分开保存**：PDB 复合物单独标记为已有实验结构；其余为后续需要预测的复合物候选。

当前结果：最终结构单位 101,336 个；Boltz 前预测队列 92,350 个。
